# Sound fix — reference backend

## Why

The native Z80 driver (`src/sound/`, generated by `tools/decompile_sound.py` and completed by
`tools/fix_sound_dispatch.py`) runs and produces sustained audio, but its per-frame sample/state hashes
still differ from MAME (235 of 300 frames in the scripted run). The remaining defect is command/timing
fidelity in the decompiled dispatcher, not silence.

For the window and release builds, the sound board now uses the **reference backend**:

- the original Z80 program on MAME's Z80 core,
- MAME's RF5C68,
- ymfm's YM3438,

through `runtime/src/sound_reference.cpp` and `tools/reference/sound/s32sound.cpp`. This is the same
sound board `s32ref` uses, so the level and content match the reference. The sound CPU is emulated; the
main V60 game remains native.

## Behaviour

- Exactly **800 output samples per 60 Hz frame** at 48 kHz: 2,880,000 bytes for 900 frames (15.0 s).
- Verified: peak 5666, RMS 1108.6 over the 900-frame autoplay sequence; reference peak 5947, RMS 1128.0.
- Attract mode is silent in the original too; gameplay is not.
- The Windows package bundles `libgcc_s_seh-1.dll`, `libstdc++-6.dll` and `libwinpthread-1.dll`.

## Selecting a backend

Default (reference, emulated):

```bash
cmake -S . -B build -DGA2_SOUND_REFERENCE=ON
```

Native decompiled Z80 backend:

```bash
cmake -S . -B build -DGA2_SOUND_REFERENCE=OFF
```

The native backend is the long-term target; a Z80 return-address model in the decompiler is the proper
fix for `sound_0473` / `sound_1094`.

## Test

```bash
GA2_AUTOPLAY=1 GA2_SOUND_RAW=sound.raw SDL_VIDEODRIVER=dummy SDL_AUDIODRIVER=dummy \
  build/bin/GoldenAxe2.exe --frames 900 --rom rom/ga2.zip
```

`sound.raw` is 48 kHz stereo s16le and should be 2,880,000 bytes for 900 frames.
